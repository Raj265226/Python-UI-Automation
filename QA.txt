Q1.What is selenium?
A.Selenium is an open-source automation testing tool primarily used to automate web applications across different browsers & OS

Q2.Selenium WebDriver
A.Selenium WebDriver is a browser automation API that allows us to interact with web applications programmatically. It can
  perform actions such as opening a browser, navigating to URLs, locating elements, clicking, typing, handling alerts, frames,
  windows, cookies, and other browser interactions.

Q3.Advantages and limitations of Selenium
A.Selenium is open source, supports multiple programming languages such as Python and Java, works across major browsers and
  OS,supports remote and parallel execution through Selenium Grid, and integrates well with frameworks and CI/CD tools.
 Its main limitations are that it is primarily designed for web-browser automation and cannot directly automate native desktop
  or native mobile applications. CAPTCHA and real MFA flows are intentionally difficult to automate. Selenium also doesn't
  provide a complete test runner or reporting solution by itself, so with Python we commonly integrate it with pytest and
  reporting tools such as Allure. Dynamic web applications can also require careful synchronization and locator design to 
  avoid flaky tests.

<----------------------------------- Browser/WebDriver Actions ----------------------------------->
Q4.close() vs quit()
A.close() closes the current browser window or tab, whereas quit() terminates the complete WebDriver session and closes all
  browser windows associated with that session.

Q5.Maximize vs Fullscreen
A.Maximize enlarges the browser to its maximized window state, whereas fullscreen requests fullscreen display mode.

Q6.Get and Set Window size
A.get_window_size() retrieves the current browser window dimensions. Ex- print(driver.get_window_size())
  while set_window_size(width, height) changes the browser window dimensions.Ex- driver.set_window_size(width, height)

<----------------------------------- Locators ----------------------------------->
Q7.Which locator should be preferred?
A.My first preference is always a locator that is unique and stable. If the application provides dedicated automation attributes
 such as data-testid, I prefer those because they are less affected by UI changes. A unique stable ID is also an excellent choice.
 Otherwise, I use stable attributes with CSS selectors, and XPath when I need text matching or parent-child/sibling relationships.
 I avoid dynamic IDs, unstable classes, indexes, and absolute XPath because they make tests brittle.

Q8.find_element() vs find_elements()?
 A.find_element() returns the first matching WebElement and raises NoSuchElementException if no element is found. find_elements()
  returns a list containing all matching WebElements, and if nothing matches, it returns an empty list

Q9.When you refresh a page, the text changes dynamically every time. How do you handle it?
A.First, I identify whether only the text is changing or the element itself is also changing.If the element is stable but the text
 is dynamic, I avoid validating the complete hardcoded text. Depending on the requirement, I validate: 
 Partial text using contains , Starts with or ends with expected text , Expected text pattern using regular expressions
 Presence or visibility of the element
 For example, if the UI displays "Welcome User12345" and the number changes after every refresh, I validate only "Welcome" or the
 expected stable portion. If the text changes asynchronously after refresh, I use an explicit wait before validating it.
 In UI automation, I avoid hardcoding dynamic values such as timestamps, random IDs, order numbers, or session-generated values
  because they make the automation unstable.

<----------------------------------- CSS ----------------------------------->
Q10.XPath vs CSS ?
A.Both XPath and CSS selectors are used to locate web elements. CSS selectors are usually shorter and convenient when stable IDs,
 classes, or attributes are available. XPath is more flexible when I need to locate elements using visible text or navigate 
 complex DOM relationships such as parent, ancestor, or siblings.

Q11.CSS Parent Traversal Limitation ?
A.CSS selectors work from parent to child and don't provide XPath-style direct child-to-parent traversal. XPath supports this 
  using parent:: or ancestor::. So when I need to locate a parent or ancestor based on a child element, I generally use XPath.

Q12. Dynamic CSS selectors and ^=, $=, *= 
A.Dynamic CSS selectors are used when an element's attribute value changes dynamically between executions. Instead of using the
 complete dynamic value, I identify the stable portion of the attribute and use CSS attribute operators.
 ^= means Starts with Xapth = [id^='user'],$= means	Ends with Xapth = [id$='name'],*= means Contains Xapth = [id*='username']

 <----------------------------------- Dropdown Handling ----------------------------------->
Q14.Dynamic dropdown ?
A dynamic dropdown is one where the options are loaded or changed at runtime. I trigger the dropdown, use an explicit wait
 for the options to become available, retrieve the options, and select the required value using stable text or attributes.
 If it's a standard <select> element I use the Select class; if it's a custom dynamic dropdown, I handle the options as
   normal WebElements.
Ex -    dropdown.click()
options = WebDriverWait(driver, 10).until(EC.visibility_of_all_elements_located((By.CSS_SELECTOR, ".dropdown-option")))
for option in options:
    if option.text == "Andhra Pradesh":
        option.click()
        break

Q15.Auto-suggestion dropdown?
A.An auto-suggestion dropdown is a dynamic dropdown where suggestions appear based on the text entered by the user. I type
 partial text, wait for the suggestion list to appear, capture the available suggestions, iterate through them, and click
  the required option based on its text or another stable attribute.

  <----------------------------------- Frames / iFrames ----------------------------------->
Q16.parentFrame() vs defaultContent()?
A.parent_frame() switches the WebDriver from the current frame to its immediate parent frame, whereas default_content() switches
  the WebDriver directly back to the main/root HTML document regardless of how deeply nested the current frame is.

Q17.Dynamic iFrame?
A.A dynamic iframe is an iframe that is loaded dynamically or whose attributes may change at runtime. I handle it using a stable
  locator and an explicit wait such as frame_to_be_available_and_switch_to_it() instead of hardcoding a changing frame ID.
  Ex - driver.switch_to.frame("frame_12345") -- its a dynamic iframe
  WebDriverWait(driver, 10).until(EC.frame_to_be_available_and_switch_to_it((
            By.XPATH, "//iframe[contains(@id,'frame_')]"))) 

  <----------------------------------- Windows & Tabs ----------------------------------->
Q18.Multiple windows and tabs handle?
A.When multiple windows or tabs are opened, I use window_handles to get all window IDs. I iterate through the handles, compare
 each one with the parent handle, and use switch_to.window() to switch between them.
 
  <--------------------------------------- Waits ----------------------------------------->
Q19.Fluent Wait?
A.Fluent Wait is an advanced explicit wait that waits for a condition with customized polling interval and exception handling.
   It keeps checking the condition repeatedly until the condition is true or the timeout occurs.
    Syntax: wait = WebDriverWait(driver,timeout=10,poll_frequency=1,ignored_exceptions=(NoSuchElementException,))
            Maximum timeout      - How long Selenium should wait.
            Polling frequency    - How often Selenium should check the condition.
            Ignored exceptions   - Which exceptions Selenium should ignore while waiting.

Q20.Polling Interval?
A.It is the frequency at which Selenium repeatedly checks whether the expected condition has been satisfied. In Fluent Wait,
  we can customize the polling interval instead of using the default polling frequency. The default polling interval in Selenium
    Python WebDriverWait is 0.5 seconds.

Q21.Ignored Exceptions?
A.Ignored exceptions in Fluent Wait allow Selenium to continue polling even when specific exceptions occur. Instead of failing
  immediately, Selenium ignores those exceptions and retries until the condition is satisfied or the timeout is reached.

Q22.Implicit Wait vs Explicit Wait?
A.Implicit Wait is a global wait applied to all element searches, whereas Explicit Wait waits for a specific condition on a specific element.
  Explicit Wait is preferred because it provides better control and reliability in automation scripts.

Q23.Explicit Wait vs Fluent Wait?
A.Explicit Wait waits for a specific condition using the default polling interval, whereas Fluent Wait is an advanced form of Explicit Wait
 that additionally allows customization of polling frequency and ignored exceptions.
 In Selenium Python, Fluent Wait behavior is implemented using WebDriverWait with the `poll_frequency` and `ignored_exceptions` parameters.

Q24.Why should time.sleep() be avoided?
A.time.sleep() should be avoided because it introduces a fixed wait, increases execution time, and can make tests flaky. Explicit or Fluent Wait
  should be used instead because they wait only until the required condition is satisfied.

Q25.Custom Wait for loader/spinner to disappear?
A.A custom wait is a user-defined wait condition used when standard Expected Conditions are not sufficient. A common example is waiting for a
  loader or spinner to disappear before interacting with page elements.

  <------------------------------------- Mouse Actions ------------------------------------->
Q26. KeyDown vs KeyUp?
A.key_up() is used to release a keyboard key after it has been pressed using key_down().

Q27.move_to_element_with_offset()?
A.move_to_element_with_offset() moves the mouse pointer to a specific X-Y coordinate relative to a web element and is commonly used when precise
  mouse positioning is required, such as sliders, charts, canvas elements, and custom UI controls.

Q28.W3C Actions API
A.W3C Actions API is the Selenium 4 standard for performing complex user interactions such as mouse hover, drag-and-drop, right-click, double-click,
  and keyboard combinations across different browsers in a consistent way.

Q29.What is WheelInput in Selenium?
A.Selenium 4 introduced WheelInput support through the W3C Actions API. Instead of executing JavaScript, it simulates real mouse wheel scrolling.
 I use ActionChains.scroll_by_amount() to scroll by a fixed number of pixels and ActionChains.scroll_to_element() to bring an element into view.
  For most applications, JavaScript scrolling is sufficient, but when I need to mimic actual user scrolling behavior, I prefer the Actions API.

  <------------------------------------- JSExecutor ------------------------------------->
Q30.JavaScript Click?
A.JavaScript Click is used to click an element using JavaScript when Selenium's normal click() method fails due to overlays, hidden elements, or
  synchronization issues.

Q31.scrollIntoView() vs scrollBy()?
A.scrollIntoView() scrolls the page until a specific web element becomes visible, whereas scrollBy() scrolls the page by a specified number of pixels
  in the X and Y direction. `scrollIntoView()` is element-based, while scrollBy() is coordinate-based.

Q32.Page Scroll – When should/should not JSExecutor be used?
A.JSExecutor Scroll should be used when an element is outside the viewport, hidden due to page scrolling, or when scrolling itself is part of the
  test scenario. It should not be used unnecessarily when the element is already visible or when proper waits can solve the issue.

Q36.How do you handle dynamic tables in Selenium?
A-I first identify the row using a unique value like an employee name or product ID. Once I find the matching row, I use a relative XPath
  to perform actions such as Edit, Delete, or reading values. This makes the automation stable even if the row order changes.

  <------------------------------------- Dynamic Elements ------------------------------------->
Q37.Dynamic id/xpath ?
  A.When a page is refreshed and the displayed text changes dynamically, I first identify whether only the text is changing or whether the entire
   element is dynamic. If only the text changes, I avoid validating the complete string. Instead, I validate the stable portion using partial text
   matching, regular expressions, or expected formats. For example, if an order number or timestamp changes every time, I verify the prefix or the
   format instead of the exact value. This approach makes the Selenium automation more stable and reduces false failures caused by dynamic data.

Q38.Dynamic Dropdown?
A.Dynamic dropdowns load their options based on user input or an API response. I first wait for the dropdown options to appear using an explicit wait,
 then capture all options with find_elements(), iterate through them, compare the visible text with the expected value, and click the matching option.
  For standard HTML <select> dropdowns, I use Selenium's Select class; for custom or React-based dropdowns, I interact with the input field and the
   dynamically generated options.

Q39.Elements appearing/disappearing?
A.If an element appears or disappears dynamically, I handle it using Selenium's Explicit Waits. If the element is expected to appear, I use
 visibility_of_element_located() to wait until it is visible before interacting with it. If the element is expected to disappear, such as a loading
  message or spinner, I use invisibility_of_element_located() to wait until it becomes invisible before proceeding to the next step. Using visibility
 and invisibility waits helps synchronize the test with the application's state, avoids timing issues, and makes the automation more stable and reliable.

Q40.How do you handle Stale Element Reference Exception?
A.A StaleElementReferenceException occurs when Selenium tries to interact with a WebElement that is no longer attached to the current DOM. This usually
 happens after a page refresh, navigation, or when JavaScript updates the page dynamically. I handle it by locating the element again after the DOM has been
  updated. If needed, I use an Explicit Wait to ensure the new element is available before interacting with it. In scenarios where the DOM updates frequently,
   I may implement a retry mechanism using try-except.

  <------------------------------------- File Upload,Download and Cookies ------------------------------------->
Q41.How do you upload a file in Selenium?
A-If the application uses a standard HTML file upload control (<input type="file">), I don't interact with the operating system's file picker. Instead,
  I use Selenium's send_keys() method to send the complete file path directly to the input element. This is the most reliable and recommended approach.

Q42.How do you handle hidden file upload controls in Selenium?
A-Sometimes the file upload control (<input type="file">) is hidden using CSS (display:none, visibility:hidden, or opacity:0), and users interact with
 a custom Upload button instead. Selenium cannot interact with hidden elements in the normal way. I first inspect the DOM to check if a hidden
  <input type="file"> exists. If it does, I use send_keys() to provide the file path directly. If required, I make the element visible using JavaScript
   before calling send_keys(). If the application uses a native operating system file dialog with no accessible file input, I use external tools like
    AutoIT or PyAutoGUI as a last resort.

          pyautogui.write(r"sampleFile.jpeg")                                           upload.send_keys(r"sampleFile.jpeg")
          pyautogui.press("enter")

Q43.Why can't Selenium automate OS dialogs?
A-Selenium is designed to automate web browsers. It interacts only with HTML elements that are part of the DOM (Document Object Model). Operating system dialogs,
 such as the Windows File Explorer, Save As dialog, Print dialog, or authentication pop-ups, are created by the operating system—not by the web page. Since these
  dialogs are outside the browser's DOM, Selenium cannot locate or interact with them.
  Ex - <button>Choose File</button> (HTML) > Window opens with dialog > It's created by Windows, not by the browser > the file dialog is not part of the HTML DOM.

Q44.How do you wait until a file download completes in Selenium?
A-Selenium doesn't provide a built-in wait for file downloads. After clicking the download button, I continuously check the download folder until the expected
  file appears. In Chrome, I also verify that the temporary .crdownload file has disappeared, which indicates that the download has completed successfully.

Q45.How do you validate the content of a downloaded file?
A-After verifying that the file has been downloaded successfully, I open the file using an appropriate Python library based on its type and validate its contents.
  For example, I use open() for text files, openpyxl for Excel files, csv for CSV files, PyPDF2 or pdfplumber for PDFs, and Pillow for images.

Q46.What is a cookie?
A.A cookie is a small piece of data stored by the browser. Websites use cookies to remember information such as login status, user preferences, session IDs,
  shopping cart details, and language settings.

  <------------------------------------- Shadow DOM ------------------------------------->
Q48.Shadow DOM and Shadow Host?
A.Shadow DOM is a browser technology used to encapsulate a component's HTML, CSS, and JavaScript from the main DOM.
  The element to which the Shadow DOM is attached is called the Shadow Host.
  The root of the Shadow DOM is called the Shadow Root.
    <book-app>  ← Shadow Host
        #shadow-root  ← Shadow Root
            <input>
            <button>
    </book-app>

Q49.What is Nested Shadow DOM?
A.Nested Shadow DOM means one Shadow Root contains another Shadow Host, which has its own Shadow Root.
<parent-component>                        host1 = driver.find_element(By.CSS_SELECTOR, "parent-component")   # Shadow Host 1
    #shadow-root                          root1 = host1.shadow_root                                          # Shadow Root 1
        <child-component>                 host2 = root1.find_element(By.CSS_SELECTOR, "child-component")     # Shadow Host 2
            #shadow-root                  root2 = host2.shadow_root                                          # Shadow Root 2
                <input id="username">     root2.find_element(By.ID, "username").send_keys("Rohit")           # Final element

Q50.Shadow DOM vs iframe?
A.Shadow DOM is an encapsulated DOM tree within the same webpage and is accessed through a Shadow Root, whereas an iframe is
  a completely separate HTML document embedded in a page and requires `switch_to.frame()` before interacting with elements
  inside it.

    <------------------------------------- Parallel Execution ------------------------------------->
Q51.What is parallel execution in pytest?
A-Parallel execution means running multiple test cases simultaneously using multiple CPU cores or processes. This reduces the
  overall execution time of the test suite.In pytest,parallel execution is achieved using the pytest-xdist plugin
  pytest -n 4

Q52.Can pytest run test classes in parallel?
A-Yes. Using the pytest-xdist plugin, pytest can execute test classes in parallel. By using the --dist=loadscope option, all
  test methods within the same class run on the same worker, while different classes are distributed across different workers.
  pytest -n 2 --dist=loadscope

Q53.Can pytest execute test methods in parallel?
A-Yes. Using the pytest-xdist plugin, pytest can execute individual test methods in parallel. Each test method is assigned to
  an available worker process, allowing multiple methods to run simultaneously and reducing the overall execution time.
  pytest -n 3 -s

Q54.When Should You Avoid Parallel Methods?
A-Depend on one another, Share the same browser instance,Use the same test data.,Write to the same file or database records,
  Rely on execution order.

Q55.What is Thread Safety?
A-Thread safety means ensuring that multiple threads or parallel workers can execute code simultaneously without causing data
  corruption, race conditions, or unexpected behavior. In test automation, thread safety ensures that parallel tests do not
   interfere with one another.

Q56.Why should we avoid using a static WebDriver in Selenium?
A-A static WebDriver means that all tests share the same browser instance. During parallel execution, multiple tests try to
 use the same WebDriver simultaneously, which causes browser conflicts, race conditions, flaky tests, and unpredictable failures.

Q57.How do you support cross-browser testing?
A-I use browser parameterization in pytest by passing a --browser command-line option. Based on the value, a Driver Factory
  creates the appropriate WebDriver, allowing the same test suite to run on Chrome, Firefox, or other supported browsers.

    <------------------------------------- Parallel Execution ------------------------------------->
58.Cross-Browser Testing?
A-Browser parameterization is the process of passing the browser name (Chrome, Firefox, Edge, etc.) as a runtime parameter
  instead of hardcoding it in the automation code.

Q59.What is a Driver Factory?
A-A Driver Factory is a design pattern that centralizes the creation of WebDriver instances. Instead of creating Chrome,
  Firefox, or Edge drivers in multiple test files, all browser initialization is handled in a single class. This makes 
  the framework more maintainable, scalable, and easier to support multiple browsers.

Q60.What are browser-specific failures?
A-Browser-specific failures occur when the same automation test passes on one browser but fails on another because browsers
 have differences in rendering,JavaScript engines,security policies, download behavior, timing, or WebDriver implementation.
